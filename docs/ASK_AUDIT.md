Source: original main commit `18c8b3c`. Demo: actual Chromium interaction with the existing box, blank baseline plus twelve questions. Live: the same thirteen inputs passed to the original production `investigate` runtime from a frozen archive of that commit, after successful Zetaris SQL and NVIDIA serving probes. Live inputs were tested at the runner boundary rather than through a second browser session. Each run used fresh memory, the same Raitu dataset and the same bounded generator.

**Verdict: No. The question does not change the plan or tools in the current model-fit workflow; the launcher box is decoration and will be removed.**

In demo mode the submit button is disabled. Typing a question and choosing Run a demo investigation always replays the same Samudra report; no POST, no changed numbers, no question-specific answer. In live mode every run completed, including hostile/off-scope inputs, but produced the same domain numbers and the generic quality status. This is not grounded question answering.

Plan key P: clarify → measure → locate → hypothesise → experiment → judge → speed → check → report. Tool key T: the tool with each of those names, once each, with empty arguments. Both modes retain P and T for every input. Live measurement SQL reads config, chats, latest token counts and prices. The planner receives the question but has a singleton action choice per model-fit step. The optional old answer-length experimental pathway was not part of these launches.
