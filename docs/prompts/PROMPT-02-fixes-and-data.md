## Step 0: review fixes from the PROMPT-01 verification
- **F1 (rate limiter lets 79 calls through in the first minute).** `TokenBucket(40)` starts full with capacity 40 and refills 40/min, so a rolling 60-second window can hold 79 requests against a 40-per-minute provider limit. The PROMPT-01 test ("the 41st call waits") was too weak; that was the prompt's fault, not yours. Replace it with a sliding-window limiter: allow a call only if fewer than `limit` calls started in the last 60 s, with `limit = NVIDIA_RPM - 2` headroom (default 38). Keep it thread-safe and abort-aware. Test: over 3 simulated minutes of saturated demand with a fake clock, no rolling 60 s window holds more than `limit` calls, and throughput still reaches at least 95% of `limit` per minute.
- **F2 (silent truncation).** `ZetarisClient.query` returns only the first page. If `len(rows) == page_limit`, either fetch further pages (if the API supports it; find out from the response body) or raise `ZetarisTruncated` unless the caller passes `allow_truncated=True`. Log `possibly_truncated` either way. Test both paths.
