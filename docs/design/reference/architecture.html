PolyToken finds out why your Telugu AI costs more, and what to change.

A product team asks one question. PolyToken measures its own chats, finds where the extra tokens come from, runs fixes against a quality bar, times real models, and reports savings in rupees. Every number on the report is recomputed by code before anyone sees it.

Where the data lives

PolyToken never reads the company database directly. One Zetaris query joins chats, measurements and reference data, which is the Track 02 "across sources" requirement doing real work.

The query that proves the federation

-- planned: sql/token_ratio_by_part.sql
SELECT t.company, t.tokenizer_spec, t.part,
       SUM(CASE WHEN t.lang_variant = 'native'
                THEN t.tokens END) * 1.0 /
       SUM(CASE WHEN t.lang_variant = 'en'
                THEN t.tokens END) AS ratio_to_en
FROM   measurements.token_counts t
JOIN   samudra.chats c
  ON   c.chat_id = t.chat_id AND c.turn = t.turn
GROUP BY 1, 2, 3;

Codex writes and runs the real version in Prompt 02 against both companies; its output becomes the first sample in logs/sample/.
